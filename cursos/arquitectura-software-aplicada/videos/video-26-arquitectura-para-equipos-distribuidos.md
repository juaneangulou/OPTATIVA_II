# Video 26: Técnicas SAST, DAST y pentesting para seguridad en software

## Título
Tres formas complementarias de buscar fallas de seguridad

## Resumen
En una plataforma logística, una persona solo debe poder consultar sus propios pedidos. Para revisar si esta protección funciona podemos analizar el código, probar la aplicación en ejecución y realizar una evaluación humana autorizada.

**SAST** busca señales de riesgo en el código sin ejecutar el programa. **DAST** prueba la aplicación mientras funciona. El **pentesting** es una revisión humana con permiso y alcance definidos que intenta demostrar el impacto de posibles fallas. Cada técnica ve aspectos distintos; ninguna garantiza por sí sola que el sistema sea seguro.

## Ideas principales
- SAST revisa el código y puede encontrar patrones que merecen investigación.
- DAST prueba el comportamiento de una aplicación en funcionamiento.
- El pentesting explora riesgos dentro de un alcance autorizado.
- Las pruebas deben usar entornos y cuentas seguros.
- Los hallazgos se interpretan, corrigen y vuelven a probar.
- Un análisis sin hallazgos no demuestra que no existan riesgos fuera de su alcance.

## Preguntas para comprobar tu comprensión
- ¿Qué técnica revisa el código sin ejecutarlo?
- ¿Qué se debe acordar antes de un pentest?
- ¿Por qué combinar varias técnicas ofrece más evidencia?
- ¿Cómo comprobarías que ya no se puede consultar el pedido de otra persona?
